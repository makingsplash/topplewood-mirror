# Схема UI-спеки (контракт компилятора)

Единственный источник правды по формату. **Поля, которого нет здесь, не существует** — компилятор
отобьёт его как ошибку, а не догадается. Если замыслу не хватает поля — это не повод придумать своё,
это заявка на расширение компилятора (роль пишет блок `NEEDS-TOOLING:`).

Спека — текстовый файл в git. Из ОДНОЙ спеки компилятор делает три вещи:

| Что | Зачем |
|---|---|
| UGUI-префаб | то, что бежит в игре |
| wireframe PNG (серые боксы) | кондишн для генерации арта — раскладка приходит из этого файла |
| скриншот PNG | обратная связь: агент видит, что собралось |

Отсюда главное свойство: **картинка, по которой генерился арт, и объект в игре собраны из одного
файла.** Расхождение «на мокапе было не так» невозможно по конструкции.

## Файлы и расположение

```
design/
  config.json              ← настройка под проект (пути, reference resolution, токены)
  tokens.json              ← цвета и типографика (опционально)
  prefabs.json             ← реестр id → путь проектного префаба (опционально)
  screens/<name>.json      ← спека экрана/попапа
  components/<name>.json   ← спека переиспользуемого компонента
```

Все пути в спеках — относительные, корни задаёт `config.json`. Абсолютных путей и имён проекта
в спеке быть не должно: спека переносима вместе с папкой `design/`.

## Корень спеки

| Поле | Тип | Описание |
|---|---|---|
| `name` | string | **Обязательно.** Имя GameObject и файла префаба |
| `kind` | string | `screen` (по умолчанию) или `component` — определяет корень вывода из конфига И анкеринг корня (см. ниже) |
| `size` | object | `{ "w": int, "h": int }` в design-px. Только для `component`: у `screen` игнорируется с предупреждением |
| `pivot` | float[2] | Pivot корня, по умолчанию `[0.5, 0.5]` |
| `controller` | string | Имя MonoBehaviour-типа, который навешивается на корень (ищется во всех сборках проекта). Именно в его поля прошиваются `bind` |
| `background` | object | `{ "sprite": ..., "color": ..., "imageType": ... }`. Без `sprite`, но с `color` — плоская заливка; полностью отсутствует — корень без Image (не ловит raycast) |
| `behaviour` | array | Блоки поведения на корне — см. ниже |
| `children` | array | Дети |

### Анкеринг корня зависит от `kind`

| `kind` | Корень | Почему так |
|---|---|---|
| `screen` | **stretch на родителя** (анкеры 0,0–1,1, нулевые отступы) | экран инстанцируют в канвас как есть, без ре-анкеринга. Фиксированный бокс reference-размера означал бы, что на экране другого соотношения затемнение не покрывает всю площадь, а safe-area считается от вымышленной высоты. Полноэкранные вещи обязаны растягиваться |
| `component` | фиксированный `size` по центру | компонент кладут в чужой контейнер, его размер — его собственное свойство |

Отсюда практическое следствие: **design-space задаёт `referenceResolution` в конфиге, а не `size` экрана.** Ширина в этом проекте фиксирована, а вертикали на высоких экранах больше — верстай так, чтобы лишняя высота уходила в растягивающиеся области, а не ломала композицию.

## Дети

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | **Обязательно.** Имя GameObject. Уникально среди сиблингов |
| `type` | string | `node` (по умолчанию, только RectTransform + опциональный фон), `image`, `text` |
| `prefab` | string | id из `prefabs.json` — вместо создания примитива инстанцируется проектный префаб. `children` при этом = deep-override существующих детей |
| `anchor` | string | Пресет привязки — таблица ниже |
| `offset` | object | Смещения. **Семантика зависит от пресета** — см. ниже |
| `size` | object | `{ "w": int, "h": int }` |
| `width` / `height` | int | Одна сторона, когда другую задаёт stretch-анкер |
| `pivot` | float[2] | Pivot. Для progress-fill, растущего от левого края — `[0, 0.5]` |
| `rotation` | float | Поворот по Z в градусах |
| `sprite` | string | Спрайт (`image`, либо фон `node`) |
| `color` | string | Токен из `tokens.json` либо `#RRGGBB` / `#RRGGBBAA` |
| `imageType` | string | `simple` (по умолчанию), `sliced` (9-slice — требует border у спрайта), `tiled`, `filled` |
| `preserveAspect` | bool | Для `image` |
| `text` | string | Текст (`text`). Пусто → плейсхолдер `«{id}»`, чтобы блок был виден на wireframe |
| `style` | string | Стиль типографики из `tokens.json` |
| `align` | string | `left` / `center` / `right` |
| `wrap` | bool | Перенос по словам. `false` (по умолчанию) — растёт вширь; `true` — переносится в пределах ширины |
| `maxLines` | int | Только при `wrap`. `>0` → лимит строк + overflow «…» |
| `layout` | object | LayoutGroup — см. ниже |
| `fit` | bool / string | ContentSizeFitter: `true` = оба измерения, `"w"` / `"h"` = одно |
| `flexibleWidth` / `flexibleHeight` | float | Доля растяжения внутри layout-группы |
| `ignoreLayout` | bool | Исключить из расчёта родительской группы |
| `hidden` | bool | `SetActive(false)` после сборки — включает контроллер в рантайме |
| `disableRaycast` | bool | Не ловить тапы (`raycastTarget = false`) |
| `behaviour` | array | Блоки поведения |
| `bind` | string | Имя поля контроллера, в которое прошить этот объект после сборки |
| `children` | array | Дети, рекурсивно |

## Токены (`tokens.json`)

Два словаря: `colors` (имя → `#RRGGBB` / `#RRGGBBAA`) и `styles` (имя → объект стиля). Спека ссылается
на них ИМЕНЕМ (`color`, `style`). Неизвестное поле стиля — ошибка сборки, как и в спеке.

### Поля стиля текста (`styles.<имя>`)

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `fontSize` | float | 36 | Кегль, design-px |
| `bold` | bool | false | `FontStyles.Bold` |
| `uppercase` | bool | false | `FontStyles.UpperCase` — регистр меняет рендер, текст в спеке остаётся как есть |
| `lineSpacing` | float | 0 | Межстрочный интервал TMP (единицы TMP, не px) |
| `characterSpacing` | float | 0 | Трекинг TMP (единицы TMP, не px) |
| `color` | string | — | Цвет-токен или hex. `color` узла перекрывает его. При `gradient` — **тинт**: TMP умножает градиент на `color`, поэтому под градиент оставляй белый |
| `font` | string | шрифт TMP по умолчанию | Путь к `TMP_FontAsset` (`.asset`) |
| `material` | string | материал шрифта | Путь к материалу TMP (`.mat`) — **обводка, тень (underlay), свечение живут здесь**, а не в компоненте. Назначается как `fontSharedMaterial`. Материал обязан сэмплить атлас ТОГО ЖЕ шрифта (делается из материала шрифта: TMP → Create → Material Preset). Чужой атлас — **ошибка сборки с `файл:id`**: TMP при загрузке молча заменил бы его материалом шрифта, и в префабе обводки бы не было |
| `gradient` | object | — | `{ "top": <цвет-токен>, "bottom": <цвет-токен> }` → вертикальный градиент заливки (`enableVertexGradient` + `colorGradient`). Только парой: половина — ошибка |

Пример «праздничного» числа: золото градиентом + тёмная обводка материалом.

```json
"reward": {
  "fontSize": 190, "bold": true, "color": "text",
  "font": "Assets/…/MyFont SDF.asset",
  "material": "Assets/…/MyFont SDF - Outline.mat",
  "gradient": { "top": "gold-hi", "bottom": "gold-lo" }
}
```

⚠ Обводка должна быть включена в самом материале keyword-ом `OUTLINE_ON`, а не одними свойствами, и пресет
должен быть материалом-АССЕТОМ — оба подвоха и цена толщины в пикселях: `docs/platform/unity-gotchas.md`
(раздел про TMP-обводку). `bold: true` на шрифте, у которого в таблице весов есть отдельный bold-ассет,
уводит глифы в материал ДРУГОГО атласа — `material` стиля до них не дойдёт; для «праздничного» числа
бери насыщенный шрифт напрямую в `font`, а не `bold`.

⚠ `prefab` с deep-override (`OverrideText`) из стиля применяет только `fontSize` и `color` — `material`,
`gradient`, `font` и прочее остаются от префаба.

### Шрифт и пресеты — рецептом, а не окном Font Asset Creator (`UiFontBake`)

Атлас для `font` и материалы для `material` выпекаются из рецепта `design/fonts/<имя>.json` командой
эндпоинта `{ "cmd": "font", "recipe": "design/fonts/<имя>.json" }` (файл-команда `Temp/uibuild_cmd.json` в
дереве с открытым редактором; результат — `Temp/uibuild_result.txt`, тот же контракт `OK…/FAILED…`).
Выход — статичный SDF-атлас (Static, без ссылки на TTF в билде) и пресеты, которые перевыпекаются ВМЕСТЕ с
атласом и сохраняют свой GUID — поэтому пресет не может остаться на старом атласе.

⚠ **GUID сохраняет файл, но НЕ под-ассеты внутри атласа.** Перевыпечка пересоздаёт текстуру атласа и
дефолтный материал шрифта с НОВЫМИ fileID (замер TASK-566: добавлен один пресет — `.asset` атласа дал
~19 тыс. строк диффа, у каждого пресета сменилась только ссылка `_MainTex`). Что из этого следует:
- текст, который стоит на ДЕФОЛТНОМ материале шрифта (стиль без `material`), держит ссылку по старому
  fileID — после перевыпечки **пересобери каждую спеку, где есть такой текст**, и проверь грепом по
  старому fileID, что висячих ссылок в `Assets/` не осталось;
- дифф атласа — бинарный по сути и конфликтует при мёрже с любой другой веткой, перевыпекавшей тот же
  шрифт: две ветки с перевыпечкой одного рецепта параллелить нельзя.

| Поле рецепта | Обязательно | Смысл |
|---|---|---|
| `source` | да | `.ttf`/`.otf` в `Assets/` (статичный инстанс начертания; вариативный — см. unity-gotchas) |
| `out` | да | путь `.asset` атласа |
| `pointSize`, `padding`, `atlas: {w,h}` | да | выпечка; **дефолтов нет** — без них отказ с названной причиной |
| `faceIndex` | нет (0) | ≠ 0 через `Font` недоступно — отказ |
| `expectStyle` | нет | сверка `faceInfo.styleName` (ловит вариативный файл, выпекшийся не тем весом) |
| `ranges` / `chars` | одно из | hex-диапазоны `"20-7E"`, `"D7"` и/или строка символов; не влезло или нет в шрифте — отказ со списком |
| `materials[]` | нет | `{ out, atFontSize, outline: {color, px}, underlay: {color, x, y, softness}, face: {texture, fit} }` — толщины в **px при кегле `atFontSize`**, цвета — токены |
| `materials[].face.texture` | да, если есть `face` | PNG растяжки в `Assets/` → `_FaceTex` (многостопная заливка лица: блик, тело, рефлекс). Делает `python3 .studio/tools/artcut.py ramp <png> --size 4x256 --stops "0:#…,…,1:#…"` (стоп 0 = верх глифа). Нет файла — **отказ** с путём. Импорт переводится в `Clamp` с пометкой в отчёте |
| `materials[].face.fit` | да, если есть `face` | На какую высоту глифа ложится 0…1 растяжки: `cap` — базовая линия…высота прописных (цифры, капс), `x` — …высота строчных, `line` — вся строка (descender…ascender). Дефолта нет |

Перевод px → доли SDF: `OutlineWidth = FaceDilate = px·pointSize / (2·padding·atFontSize)` (кант целиком
снаружи), смещение тени — `px·pointSize / (padding·atFontSize)`. Двойка подписана кадром, механизм —
`docs/platform/unity-gotchas.md` (раздел про цену единицы `_OutlineWidth`).

**Текстура лица (`face`) — когда двух цветов `gradient` мало.** Вершинный градиент красит углы квада глифа
двумя цветами; блик в верхней трети и рефлекс у кромки им не выразить. Как ложится:

- UV лица в шейдере TMP — это UV2 меша, а его строит **компонент** по `verticalMapping`. `Character` (дефолт)
  растягивает 0…1 на прямоугольник КАЖДОГО глифа с паддингом — у «+» и «7» блик встаёт на разную высоту.
  `Line` — по высоте строки, одинаково для всех глифов. Компилятор ставит `verticalMapping = Line` сам, если у
  материала стиля есть `_FaceTex`: маппинг — свойство компонента, его не положить в материал.
- Под `Line` выпечка калибрует тайлинг/офсет `_FaceTex` по метрикам ЭТОГО шрифта, чтобы 0…1 легли на полосу
  `fit`. Вне полосы (выносной элемент, овершут «0», дилейт канта) — край растяжки (`Clamp`).
- Шейдер пресета становится полным `TextMeshPro/Distance Field` (в мобильном SDF текстуры лица нет).
  Он тяжелее мобильного — брать для наградных чисел и надписей, а не для массового текста.
- Лицо = растяжка × `color` × `gradient`: под растяжку цвет стиля — белый, `gradient` не задавать.
- Калибровка верна для строки ОДНОГО шрифта и кегля: `<size>`, спрайты и fallback-глифы в строке меняют её
  ascender, и полоса сдвигается.

Класс: любое глянцевое/металлическое число или надпись наград — сумма монет, множитель «x2», «LEVEL UP»,
счётчик звёзд. Пример:

```json
{ "out": "Assets/…/Font SDF - Reward.mat", "atFontSize": 108,
  "outline": { "color": "reward-outline", "px": 8 },
  "face": { "texture": "Assets/…/reward-gloss.png", "fit": "cap" } }
```

## Пресеты привязки

| Пресет | anchorMin | anchorMax | Что задаёт `offset` |
|---|---|---|---|
| `stretch` | (0,0) | (1,1) | `left`, `right`, `top`, `bottom` — отступы от краёв |
| `top-stretch` | (0,1) | (1,1) | `left`, `right`, `top`; **`height` обязателен** |
| `bottom-stretch` | (0,0) | (1,0) | `left`, `right`, `bottom`; **`height` обязателен** |
| `left-stretch` | (0,0) | (0,1) | `top`, `bottom`, `left`; **`width` обязателен** |
| `right-stretch` | (1,0) | (1,1) | `top`, `bottom`, `right`; **`width` обязателен** |
| `center` | (0.5,0.5) | (0.5,0.5) | `x`, `y` |
| `top-left` · `top-center` · `top-right` | y=1 | y=1 | `x`, `y` |
| `bottom-left` · `bottom-center` · `bottom-right` | y=0 | y=0 | `x`, `y` |
| `left-center` · `right-center` | x=0 / x=1 | то же | `x`, `y` |

**Смешивать нельзя, и это ошибка сборки, а не молчание.** `left`/`right`/`top`/`bottom` на точечном
анкере и `x`/`y` на stretch-анкере компилятор отбивает с указанием файла и `id`. Причина явная:
в родственных реализациях такие ключи молча игнорировались, и вёрстка «почему-то в углу» отлаживалась
глазами вместо чтения отчёта.

## Целые координаты

Все `offset`, `size`, `width`, `height` — **целые**. Дробные дают размытые края и артефакты
pixel-snap. Компилятор пишет предупреждение и округляет. Дробным разрешено быть только `pivot`
(это пропорция) и `rotation`.

## Размер: что будет, если его не задать

| Контекст | `size` задан | `size` НЕ задан |
|---|---|---|
| Без layout-группы, без анкера | центр + фиксированный размер | stretch на весь родитель |
| Внутри layout-группы | `LayoutElement.preferred` (НЕ `sizeDelta` — его группа перетирает) | размер считает группа |
| С анкером | анкер + `offset` | размер из stretch-сторон анкера |

**`anchor` внутри layout-группы — ошибка сборки.** Позицию и размер там задаёт группа, анкер был бы
затёрт молча. Нужен ребёнок вне раскладки группы — `ignoreLayout: true`: такой узел группа не трогает,
и он раскладывается сам, как вне группы — свой `anchor` + `offset` + `size` (строки «Без layout-группы» и
«С анкером» таблицы выше). Типичный случай — шапка, крестик или бейдж поверх панели с авто-высотой
(`fit: "h"`): узел держится за кромку панели, а не за фиксированную координату. До TASK-566 компилятор
анкер такому узлу не применял, а `size` клал в `LayoutElement.preferred*`, который группа для него же
игнорирует, — узел оставался с дефолтным rect при чистом отчёте (тест `UiIgnoreLayoutAnchorTests`).

## Layout-группы

```json
"layout": { "dir": "vertical", "spacing": 16, "padding": { "left": 24, "right": 24, "top": 16, "bottom": 16 },
            "align": "upper-center", "controlSize": true, "forceExpand": false }
```

| Поле | Значения |
|---|---|
| `dir` | `vertical`, `horizontal`, `grid` |
| `spacing` | int |
| `padding` | `{left,right,top,bottom}` |
| `align` | `upper-left` … `lower-right`, `middle-center` |
| `controlSize` | контролировать размер детей (по умолчанию `true`) |
| `forceExpand` | раздавать свободное место по **главной** оси (по умолчанию `false`). Поперечную ось дети заполняют **всегда**: строка в вертикальной группе — во всю ширину группы |
| `cell` / `constraintCount` | только для `grid` |

**Правило:** layout-группа нужна для динамического набора детей или автосайз-контента. Статичную
композицию — даже из двух элементов — верстай `anchor` + `offset`: она предсказуема, попадает в
wireframe один-в-один и не двигается от порядка детей.

## Блок `behaviour`

Список объектов `{ "type": "...", ...параметры }`. Применяется **после** создания детей.
Каталог типов не живёт в этом файле — он собирается из зарегистрированных хэндлеров, потому что
проект добавляет свои. Что доступно сейчас — команда `ui-build catalog`.

Переносимое ядро даёт только чистый UGUI: `Button`, `ContentSizeFitter`, `LayoutElement`,
`ScrollRect`, `RectMask2D`, `CanvasGroup`. Всё, что зависит от фреймворка проекта (анимации
показа/скрытия, safe-area, локализация, свои контроллеры состояний), проект добавляет своим
хэндлером — см. `PORTING.md`.

Неизвестный `type` — ошибка сборки со списком известных. Не тихий пропуск.

## `bind` — прошивка ссылок

`"bind": "_closeButton"` означает: после сборки найти на корневом `controller` поле с таким именем
и записать в него этот объект. Тип поля решает, что именно пишется — сам GameObject или компонент
с него. Не найденное поле, занятый чужим объектом слот, отсутствие `controller` — всё попадает в
отчёт сборки. Смысл: агент не может «перетащить ссылку в инспекторе», а без ссылок попап мёртв.

## Пересборка (`isUpdate`)

Если префаб уже существует, сборка **не создаёт его заново**:

- **корневой GameObject сохраняется** — вместе с GUID ассета и с компонентами, которых нет в спеке
  (например навешенный человеком MonoBehaviour остаётся);
- **дети пересоздаются** из спеки целиком;
- **managed-компоненты, ушедшие из спеки, удаляются** с корня: если хэндлер объявляет тип
  управляемым, а в новой спеке этого блока нет — компонент снимается, а не остаётся мусором.

🛑 **Не удаляй `.prefab` руками, чтобы «пересобрать с нуля».** Это уносит и GUID (все ссылки на
префаб превращаются в missing), и навешенные вручную компоненты корня. Пересборка — команда
компилятора.

## Отчёт сборки

Каждая сборка пишет отчёт: что создано, что перестроено, все ошибки и предупреждения с `файл:id`.
Красный отчёт = префаб не записан. Это и есть гейт: «собралось» не бывает «почти».
