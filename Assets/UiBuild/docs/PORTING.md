# Перенос компилятора UI в новый проект

Тула переносима так же, как роли студии: **ядро не знает ни одного имени проекта**. Всё проектное
входит через один конфиг и через свои хэндлеры.

## Что переносится как есть

Папка **`Assets/UiBuild/`** целиком — ядро, реестр, переносимые UGUI-хэндлеры, рендерер, файловый
эндпоинт для агента (`UiBuildAgentEndpoint`), батч-энтрипоинт (`UiBuildBatch`), меню, эта
документация. Плюс обёртка **`.studio/tools/ui-build.sh`**.

Зависимостей нет: JSON читается своим парсером (не Newtonsoft), ссылок на сборки проекта в
`iliai.uibuild.editor.asmdef` нет — только `UnityEngine.UI` и `Unity.TextMeshPro`.

**Почему в `Assets/`, а не в `Packages/`.** Пробовал пакетом (`Packages/com.iliai.uibuild`): Unity
не разрешает новый embedded-пакет по `AssetDatabase.Refresh()` — нужен фокус редактора или рестарт.
Тула при этом перестаёт проходить тот же компайл-гейт, которым студия проверяет весь остальной код,
то есть её нельзя проверить в том же прогоне, в котором её правишь. Под `Assets/` сборка идёт сразу.

## Как обёртка зовёт компилятор: два транспорта одной команды

`ui-build.sh` подаёт РОВНО один JSON-контракт
(`{"cmd":"catalog|build|buildAll|render","spec":…,"flat":…,"out":…}`) и получает результат
`OK…` / `FAILED…` — но доставляет команду двумя путями, выбор автоматический и **печатается**
(`транспорт=EDITOR|BATCH`), молчаливой подмены нет:

| Транспорт | Когда | Команда → результат |
|---|---|---|
| **EDITOR** | в дереве открыт Unity (человек за редактором; основное дерево) | файл `Temp/uibuild_cmd.json` (тиками слушает `UiBuildAgentEndpoint`) → `Temp/uibuild_result.txt` |
| **BATCH** | worktree-слот пула БЕЗ редактора | env `UIBUILD_CMD` (headless `Iliai.UiBuild.UiBuildBatch.Run`) → `Logs/uibuild-batch-result.txt` (env `UIBUILD_RESULT`) |

Оба транспорта зовут один диспетчер (`UiBuildAgentEndpoint.Execute`), поэтому «у редактора собралось /
у батча нет» не может стать двумя разными процессами.

**Почему у батча результат не в `Temp/`.** Unity удаляет весь `Temp/` при выходе редактора. Живой
эндпоинт держит редактор открытым — `Temp/` жив весь сеанс. Батч же пишет и тут же выходит: `Temp/`
(с `Temp/uibuild_result.txt`) исчезает раньше, чем обёртка прочитает файл. Поэтому батч кладёт результат
в ПЕРСИСТЕНТНЫЙ `Logs/uibuild-batch-result.txt` (путь задаёт обёртка через env `UIBUILD_RESULT`);
содержимое-контракт (`OK…`/`FAILED…`) идентично эндпоинту.

**Различитель — `Temp/UnityLockfile`** (его держит только живой Unity). Обёртка сперва даёт короткое
окно (`UIBUILD_EDITOR_WAIT`, дефолт 10с) на ответ редактора; если ответа нет и лок **есть** — в дереве
живой редактор занят компиляцией: второй Unity сюда не запустить, поэтому батч НЕ включается и обёртка
ждёт редактор до полного `UIBUILD_TIMEOUT` (поведение основного дерева без изменений). Лока **нет** —
редактора нет (слот) → батч. Форс-батч при зависшем редакторе / stale-локе: `UIBUILD_FORCE_BATCH=1`.

Батч берёт тот же лок дерева `<repo>.lock`, что `compile-gate.sh`/`run-sim.sh` (один батч на дерево;
занято → exit 2), лог пишет в `Logs/uibuild-batch.log`. Батч-энтрипоинт вызывается БЕЗ `-quit`: код
выхода ставит сам `EditorApplication.Exit` (как у `LevelSimBatch`).

## Что пишется заново под новый проект

| Что | Где | Зачем |
|---|---|---|
| `design/config.json` | корень проекта | пути (спрайты, куда класть префабы, куда рендерить), reference resolution |
| `design/tokens.json` | корень проекта | палитра и типографика этого проекта |
| `design/prefabs.json` | корень проекта | реестр `id → путь` готовых префабов, на которые ссылаются спеки |
| Проектные хэндлеры `behaviour` | любая Editor-сборка проекта | всё, что зависит от UI-фреймворка проекта: анимации показа/скрытия, safe-area, локализация, свои контроллеры |
| Проектные post-build шаги | там же | контракт экрана: регистрация в загрузчике ассетов, генерация констант, атласы |

В этом проекте примеры лежат в `Assets/Game/Scripts/Editor/UiBuild/`:
`SafeAreaHandler` (обёртка над компонентом safe-area), `ScreenRegistrationStep` (Addressables +
слияние констант экранов) и `RevealHandlers.cs` — анимация показа экрана данными (`Reveal` на узле,
`ScreenReveal` на корне как `IWindowAnimator`, пост-шаг сверки; DOTween + SayKit-стек).

## Точки расширения

```csharp
[UiHandler("МойБлок")]
public sealed class МойХэндлер : IUiBehaviourHandler
{
    public IEnumerable<Type> ManagedTypes => new[] { typeof(МойКомпонент) };
    public void Apply(UiBuildContext ctx, GameObject target, UiBehaviourSpec spec) { ... }
}
```

- Обнаружение автоматическое (`TypeCache`) — реестр править не нужно, класс может лежать в любой
  Editor-сборке проекта.
- `ManagedTypes` — то, чем хэндлер владеет. Ушёл блок из спеки → компонент снимается при пересборке.
  Без этого на префабе копится мусор от прошлых версий вёрстки, невидимый в диффе.
- Параметры блока читай через `spec.Reader(ctx.Report)` и **обязательно** вызывай `Finish()` — тогда
  опечатка в параметре станет ошибкой сборки, а не молчаливым дефолтом.
- Ошибки пиши в `ctx.Report`, а не в `Debug.Log`: отчёт — это то, что читает роль и гейт.

`IUiPostBuildStep` — то же самое для шагов после записи префаба (`Order` задаёт порядок).

## Чек-лист переноса

1. Скопировать `Assets/UiBuild/` и `.studio/tools/ui-build.sh`.
2. Завести `design/config.json` под пути нового проекта; проверить `bash .studio/tools/ui-build.sh catalog` — он печатает, что тула видит.
3. Завести `design/tokens.json` (палитру можно заглушкой до арт-дирекшна).
4. Написать проектные хэндлеры под UI-фреймворк проекта; проверить, что они появились в `catalog`.
5. Написать post-build шаг под контракт экрана проекта (как экран попадает в загрузчик).
6. В дашборде: `design` в `writerPaths` и именованный грант `Bash(bash .studio/tools/ui-build.sh*)` кодовой роли.
7. Проверить круг целиком на одной проверочной спеке: `build` → `render` → посмотреть PNG глазами.

## Границы версии 0.1 (честно)

- **Вариантов префабов нет** (`base` / `childOverrides` из родственных схем не реализованы) — пока
  два похожих экрана = две спеки.
- **Импорт-настройки спрайтов не управляются**: `border` для 9-slice ставится в импортёре спрайта.
  Компилятор проверяет, что border не нулевой, и падает с ошибкой, если `imageType: "sliced"` стоит
  на спрайте без border.
- **Скриншот — не play-mode.** Рендер идёт в редакторе: видно раскладку, арт, шрифты; НЕ видно
  рантайм-состояний, анимаций показа и данных, которые проставляет контроллер.
- **Атласы и Addressables — дело проектных шагов**, ядро в них не лезет.
- **Пересборка не diff-стабильна и меняет fileID детей.** Корень сохраняет GUID ассета (на этом
  стоит `isUpdate`), но дети пересоздаются, поэтому диff префаба всегда на весь файл, а **внешняя
  ссылка на ВНУТРЕННИЙ объект префаба после пересборки станет missing**. Ссылки контроллера это не
  задевает — они восстанавливаются `bind` на каждой сборке, ровно для этого он и существует. Но
  ссылку из сцены или другого префаба на ребёнка внутри собранного префаба ставить нельзя.
- **Рендер может грязнить fallback-атлас TMP.** Если у шрифта проекта нет нужных глифов (здесь —
  кириллицы в `SairaSemiCondensed-Black SDF`), TMP на каждом рендере дописывает их в общий
  `LiberationSans SDF - Fallback.asset`, и в git появляется диff в файле, к которому вёрстка
  отношения не имеет. Это дефект НАБОРА ШРИФТОВ проекта, а не компилятора: лечится шрифтом с нужным
  языком. До того — не коммить этот ассет вместе с вёрсткой.
